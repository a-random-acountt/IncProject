# Void

The most useless app possible, built to genuinely shippable quality.

Void is an iOS SwiftUI app whose only real feature is a button that
does nothing. It counts how many times you've pressed it and how many
days in a row you've bothered to. That's the whole app. It's dark-only
by design, styled after Vercel's black theme (near-pure-black
surfaces, hairline borders, a single blue accent used sparingly, an
inverted white-on-black primary CTA), fully usable, has an actual test
suite, and takes itself completely seriously.

## What it does

| Screen | What's there |
|---|---|
| **Home** | The Do Nothing button, a total-click counter, and the current streak |
| **Settings** | Sound toggle, reset progress, version/total-clicks info |

Tapping the button logs a click, gives a haptic bump, plays a click
sound (toggleable), and shows a small toast confirming that, yes,
nothing happened.

## Architecture

One target, laid out exactly like Xcode's own "New Project" template -
the app's folder sits at the repo root, next to `Void.xcodeproj`, not
nested under a `Sources/` wrapper:

```
Void.xcodeproj/         <- generated from project.yml, checked in and ready to open
Void/                   <- the app target
Void/VoidApp.swift      <- @main entry point
Void/Assets.xcassets    <- app icon + Vercel-black color assets, right next to the code
Void/Views/             <- screens + components
Void/Models/            <- NothingStore, streaks, stats, persistence
Void/Support/           <- theme tokens, haptics, sound
VoidTests/              <- unit tests covering streaks, stats, and number formatting
project.yml             <- XcodeGen source of truth for the iOS app
```

`Void.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml` and **checked into the repo** - clone and open it,
no generation step required. `project.yml` stays the source of truth:
if you add/remove/rename files or change build settings, edit
`project.yml` and re-run `xcodegen generate` to keep the checked-in
`.xcodeproj` in sync (see below).

`VoidTests` is a normal Xcode unit test target with `Void` as its host
application - run it from Xcode's Test navigator or with **⌘U**. All
tests live in `Void/Models/` logic (streak math, stats, number
formatting) that happens to have zero SwiftUI imports, which is why it
was straightforward to verify correct - see below - without ever
needing a Mac in the loop.

## Running the app

You'll need a Mac with **Xcode 26+** (for the `.glassEffect()` API the
toast uses — the project targets iOS 26).

1. Open `Void.xcodeproj` directly - it's checked in, no generation step
   needed.
2. Pick the **Void** scheme, select a run destination (an iOS 26
   simulator, or a device), and hit Run. The first time, Xcode will
   ask you to pick a signing team for "Automatically manage signing"
   — any personal team works for local development.

There are no third-party dependencies - just SwiftUI and system
frameworks, so there's nothing for Xcode to resolve on first build.

### Changing the file layout or build settings

`project.yml` is the source of truth `Void.xcodeproj` was generated
from. If you add, remove, or rename source files, or change a build
setting, edit `project.yml` and regenerate rather than hand-editing
the `.xcodeproj`:

```sh
brew install xcodegen   # if you don't have it
xcodegen generate
```

This was verified end-to-end in a Linux environment without Xcode by
building XcodeGen from source with `swift build` and running it
against `project.yml`, then re-opening the result with XcodeGen's own
`XcodeProj` parser to confirm both targets, the `VoidTests` → `Void`
host-application wiring, the asset catalog's build phase, and the
shared scheme's test action all round-trip correctly - the strongest
check available without a Mac. The logic under `Void/Models/` was
additionally verified by copying it into a throwaway Swift package and
running `swift test` against it before it ever touched Xcode. Still,
treat the very first Xcode open as the real test.

The app forces dark mode (`UIUserInterfaceStyle: Dark` +
`.preferredColorScheme(.dark)`) — there's no light theme, by design.

To change the app icon, replace
`Void/Assets.xcassets/AppIcon.appiconset/icon-1024.png` with a new
1024×1024 PNG.
